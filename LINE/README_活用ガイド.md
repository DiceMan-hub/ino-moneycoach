# LINE 構造化データの他プロジェクト活用ガイド

LINE で構造化したメモ（`processed/`）を、ニュースレター・note・議事録・プロジェクトで**確実に再利用する**ためのルールとワークフロー。

---

## 1. 活用の原則

- **LINE は「一次メモの倉庫」**：断片的なインプットを category + title で整理済み。他プロジェクトは**参照元としてリンク**し、重複執筆を避ける。
- **参照は Obsidian の `[[リンク]]` で行う**：プロジェクト側のドキュメントから「どの LINE メモを参照したか」を明示すると、後からトレース・更新がしやすい。
- **1プロジェクト1〜数本に絞る**：号や記事ごとに「今号で使う LINE メモ」を 2〜3 本に限定し、深掘りする。

---

## 2. プロジェクト別の活用パターン

### ニュースレター（03_NewsLetter）

| フェーズ | 使い方 |
|:--|:--|
| **Phase 1（企画）** | メインテーマ・CTA 候補を決めるとき、`LINE/_index.md` の「旅行・マイレージ」「クレカ」を流し読み。特集のネタ候補として `[[LINE/processed/マイレージ/〇〇]]` を 1〜2 本ピックする。 |
| **特集執筆** | 選んだ LINE メモを**参照元**として開き、要約・自分の体験・追記だけをドラフトに書く。元メモはリンクで明示（例：「参考：[[JALビジネスをAAマイルで東南アジア]]」）。 |
| **今週のワンポイント** | 1〜3 行に収めるため、LINE の「結論だけ」を抜き出して使う。必要なら `[[processed/クレカ/〇〇]]` などをリンク。 |

**段取りへの組み込み例（任意）：**

```markdown
### 今号で参照する LINE メモ（2〜3本に絞る）
- [[LINE/processed/マイレージ/JALビジネスをAAマイルで東南アジア]]
- [[LINE/processed/クレカ/海外事務手数料無料のカード3選 Revolut Wise IDARE]]
```

---

### note・記事（04_note / ブログ）

| 用途 | 使い方 |
|:--|:--|
| **記事の種** | LINE の「ビジネス」「クレカ」「マイレージ」から、読者ニーズに合うタイトルを選び、1本の記事に拡張する。 |
| **根拠・出典** | 記事内で「こういう情報がある」と書くとき、元が LINE のメモなら `[[processed/〇〇]]` をリンクしておく。 |
| **シリーズ化** | 例：アメックス移行ガイドと、LINE の「松井証券ポイントでJALマイル」「三菱UFJマネ活でJALマイル」を組み合わせて「ポイ活×マイル」特集にする。 |

---

### プロジェクト（00_Projects / 05_Minutes）

| 用途 | 使い方 |
|:--|:--|
| **企画・戦略** | 議事録やロードマップに「根拠・トレンド」として LINE メモを貼る。例：「DM で多い質問 → [[ANA SFC 取得後のカード選び 一般とゴールド]] を要約して FAQ に」。 |
| **比較・一覧** | 既存の「特典航空券ルール比較」などに、LINE の「アライアンス別特典検索」「JAL特典空席検索 PointsYeah活用法」を**参照リンク**で追加し、一元化する。 |

---

### AI・業務効率（06_BusinessKnowledge / スキル）

- LINE の **AI カテゴリ**（Claude Code、Cowork、Obsidian×Antigravity など）は、`.cursorrules` や `CLAUDE.md` の「参考リンク」にまとめておくと、エージェントや自分がすぐ参照できる。
- 例：`CLAUDE.md` に「LINE メモの AI まとめ：[[LINE/_index#🤖 AI・テクノロジー活用]]」を追記。

## 3. 運用ルール（推奨）

1. **参照したらリンクを残す**  
   ニュースレターの段取り・ドラフト、note の下書き、議事録の「参考」欄に `[[LINE/processed/カテゴリ/タイトル]]` を 1 行書く。

2. **インデックスは MOC のまま使う**  
   `LINE/_index.md` は「カテゴリ別・日付順」の MOC。企画時はここから「今月のマイレージ」「今月のクレカ」をざっと見て選ぶ。

3. **1号・1記事あたり 2〜3 本まで**  
   多く参照しすぎると焦点がぼける。特集や CTA に直結する 2〜3 本に絞る。

4. **日付（frontmatter）を意識する**  
   LINE の `date` が古いものは、キャンペーン・制度変更の記事で使うときに「当時は〇〇。現在は要確認」と一文添える。

## 4. クイック参照

| やりたいこと | 開くもの |
|:--|:--|
| 特集のネタを探す | [[LINE/_index]] → 該当カテゴリの直近 10 件 |
| 今号で参照するメモを決める | 段取りの「今号で参照する LINE メモ」に 2〜3 本リンク |
| 記事の種・根拠を足す | LINE の該当 note から `[[processed/〇〇]]` を本文に追加 |
| AI・ツールの参照をまとめる | [[LINE/_index#🤖 AI・テクノロジー活用]] を CLAUDE.md 等にリンク |

---

## 5. まとめ

- **LINE 構造化データ = 他プロジェクトの「参照用ナレッジベース」**  
  コピペで増やすのではなく、**リンクで参照**し、プロジェクト側で要約・体験・追記する。
- **ニュースレター**：企画時に _index を見てネタを選び、段取りに「今号で参照する LINE メモ」を 2〜3 本書く。
- **note・議事録・プロジェクト**：根拠や種として `[[LINE/processed/カテゴリ/タイトル]]` を貼り、トレース可能にする。

これで「LINE に貯めたメモが、どの号・どの記事・どの会議で使われたか」がリンクから逆引きでき、今後のプロジェクトでも同じメモを安全に再利用できる。
