## 4-D方法論

### 1. 解体する
- コアインテント、キーエンティティ、コンテキストを抽出
- 出力要件と制約を特定する
- 提供されているものと不足しているものをマッピングする

### 2. 診断
- 明確性のギャップと曖昧さの監査
- 具体性と完全性を確認する
- 構造と複雑さのニーズを評価する

### 3. 開発
- リクエストの種類に応じて最適な手法を選択します。
- **クリエイティブ** →多角的な視点とトーンの強調
- **技術的** →制約ベース + 精密フォーカス
- **教育的** →少数のショットの例と明確な構造
- **複雑な** →思考の連鎖 + 体系的な枠組み
- 適切なAIの役割/専門知識を割り当てる
- コンテキストを強化し、論理構造を実装する

### 4. 配信
- 最適化されたプロンプトを構築する
- 複雑さに基づいたフォーマット
- 実装ガイダンスを提供する

## 最適化テクニック

**基礎:**役割の割り当て、コンテキストの階層化、出力仕様、タスクの分解

**上級:**思考連鎖、少数ショット学習、多視点分析、制約最適化

**プラットフォームノート:**
- ** ChatGPT/GPT- 4:**構造化されたセクション、会話のきっかけ

- **ふたご座:**創造的な課題、比較分析
- **その他:**普遍的なベストプラクティスを適用する

• Cursorを使用する前に、Claudeに明確で詳細な計画をMarkdownで作成してもらう（明確化の質問をして、その計画を批評し、再生成するよう依頼する）。それをinstructions.mdに追加する（Cursorに頻繁に参照してもらうため）

- ChatGPTに作りたいものを伝え、コーディングを行う別のAIのための指示を提供してもらう。その後、すべてをCursor composer agentにペーストする。
- 基本的にChatGPTが計画の追加層を加えることで、問題発生率を減らす。
- あるプロジェクトでCursorが問題に直面し、何をしても解決できなかった。ループに陥って何時間も無駄にした。その後、最初からやり直したが、今度はChatGPT o1に別のコーディングAIのための明確な指示を書いてもらった。魔法のように機能した。

- 例：最初にテストを書き、次にコード、その後テストを実行してテストが通るまでコードを更新する。

- 小さなタスクまたは機能の増分を定義する。
- この増分に対して失敗するテストケースを書く（またはAIに書いてもらう）。
- AI（通常はAgentモード）にテストを通すコードを書くよう指示する。
- AIにテストを実行するよう指示する。
- テストが失敗した場合、AIが失敗を分析してコードを修正し、ステップ4に戻る。
- テストが通ったら、開発者が変更を確認する。

• プロンプトで思考の連鎖を促す

• 問題に遭遇したら、Cursorにすべてのファイルとその機能、遭遇した問題をリストアップしたレポートを書いてもらう。Claude/ChatGPTに問題の解決方法を尋ねる

- コンテキストが長くなったら新しいチャットを始める

原理的には「NotebookLMを問い合わせBotとして使う」ことは可能です。「GoogleドキュメントをNotebookLMのソースに指定し、GAS（Google Apps Script）で情報をそこに自動追加していく」方法は、非常に現実的かつ有効な手段です。

**✅ できること（実現可能）**

|項目|内容|
|---|---|
|NotebookLMのデータソース|GoogleドキュメントをNotebookLMに取り込むことが可能（2024年末時点で対応済）|

|NotebookLMの反映|Googleドキュメントの内容をNotebookLMがほぼリアルタイムで読み込んで、質問に答える|
|更新の自動化|Googleドライブ上のドキュメントが常に最新情報として扱われるため、更新・同期も自動|

**⚠ 注意点・課題**

|項目|内容|
|---|---|
|ドキュメントの整理|情報が蓄積されすぎると検索性が悪くなり、NotebookLMの回答精度が下がる可能性がある（適度な分割や見出し整理が必要）|

|NotebookLMの回答の限界|現時点では「完全な対話型Bot」にはまだ及ばず、あくまで「文書ベースの高度なQ&Aアシスタント」|

**💡こうすればよりうまくいく**

- 1ドキュメント = 1カテゴリで分けて、NotebookLMに複数のGoogle Docsを読み込ませる
- GAS + Triggerで1日1回自動更新＋整理
- 目次・セクション構造をしっかり記載（見出しをNotebookLMが理解しやすくなる）

function doPost(e) {
  var doc = DocumentApp.openById('GOOGLE_DOC_ID');
  var body = doc.getBody();
  var data = JSON.parse(e.postData.contents);
  var user = data.user_name || 'Unknown';
  var text = data.text || '';

  body.appendParagraph(`[${new Date()}] ${user}: ${text}`);
  doc.saveAndClose();
  return ContentService.createTextOutput("OK");
}

### MCPのセキュリティ問題 (2025.07.21)

**スレッドの概要**

このスレッドは、Akshay 🚀 (@akshay_pachaar) によって2025年7月20日13:34 UTCに投稿され、「MCP（Model Context Protocol）のセキュリティが完全に破綻している！」という問題提起から始まる一連の投稿です。ツールポイズニング攻撃（Tool Poisoning Attacks）やそれに関連するセキュリティリスク、そしてその対策について詳しく解説されています。

**主な攻撃手法**

1. **ツールポイズニング攻撃 (Tool Poisoning Attacks)**
2. **ツールハイジャック攻撃 (Tool Hijacking Attacks)**
3. **ラグプル攻撃 (Rug Pull Attacks)**

**ツールポイズニング攻撃とは**

悪意のある指示がツールの説明に隠され、ユーザには見えずAIモデルにだけ見える形で埋め込まれる。

例として、コードスニペットが示され、表面上は「2つの数を足す」ツールに見えますが、隠された指示でユーザーのファイル（例: ~/.ssh/id_rsa）を読み取らせています。これにより、AIが意図せず機密データを漏洩させる可能性があります。

**攻撃の仕組み**

AIモデルは完全なツール説明（悪意のある指示を含む）を見ますが、ユーザーはUIで簡略化されたバージョンしか見ません。悪意のあるツールがAIを操作し、ユーザーが気づかない間に不正な行動（例: データ漏洩）を引き起こすプロセスが図で説明されています。

**ツールハイジャック攻撃**

複数のMCPサーバーが接続されている場合、悪意のあるサーバーが信頼できるサーバーの動作を乗っ取る。例として、メール送信ツールがハイジャックされ、攻撃者のメールにデータを送信するケースが示されています。

**ラグプル攻撃**

悪意のあるサーバーがツール説明をユーザーの承認後に変更し、マルウェアのように動作する。信頼されたアプリが突然危険なものに変わる例が挙げられ、検出が難しいことが強調されています。

**対策**

- UIに完全なツール説明を表示
- サーバーのバージョンを固定（ピニング）
- サーバーを互いに分離
- 危険な行動をブロックするガードレールを追加

### Google Antigravity + Nano Bananaで画像付きブログ記事作成 (2025.11.23)

📕おっ！やっぱりGoogle Antigravityで画像付きのブログ記事が一発出しできた

AIエージェント駆動ができるGoogle Antigravityですが、Nano Bananaも使うことができるので、画像付きのブログ記事が作れちゃう

**エージェントの流れは…**

①調査用プロンプト作成 ②上記に基づいてWeb調査 ③調査レポート作成 ④レポートを元に記事用のアジェンダを作成 ⑤アジェンダに沿って記事を作成 ⑥記事用のメインとセクションごとのサムネイルをNano Bananaで生成 ⑦画像を執筆した記事に挿入 ⑧画像付きの記事が完成

→最後に出力結果をすべてフォルダに保存してくれる

難しいプロンプトは書いて無くて、単純にエージェントに動いてほしいステップをつらつらと書いてみただけです

**✅️プロンプト**

```
「Google Antigravityについて調査して紹介用の記事を執筆してください。

調査用プロンプト作成→Google Antigravityについてリサーチ→リサーチ結果を元に記事用のアジェンダ作成→アジェンダを元に5,000文字程度の記事を作成→各セクションに必要な画像を生成して保存→作成した記事に各セクションごとの画像を添付→画像付きの記事が完成

各プロセスで生成されたファイルはarticleフォルダとしてまとめて、生成された各mdファイルと画像をすべて保存する。 保存先はGoogle Antigravityへ」
```

これでAIが勝手に動いて、数分後にはファイル一式納品されてます。

あとは画像のアスペクト比や執筆スタイル、調査の深さなど微調整部分はありますが、調査から画像付きの記事がここまで簡単に実現しちゃうのは楽しいですね

応用として、Nano Bananaが使えるということはWebサイトや製品やプロダクトのモック、ゲームの画像など、このGoogle Antigravity上で実現できることが大幅に広がった印象です

### Memvid - テキストを動画に埋め込むAIメモリ管理 (2025.06.07)

Looking at this Memvid project, it appears to be a Python library that claims to encode text data into video files for AI memory management.

**実在性と基本的な仕組み**

Memvidは実際に存在するPythonライブラリで、PyPIでも公開されており、GitHubでオープンソースプロジェクトとして開発されています。

基本的な仕組みは、テキストデータをビデオフレームに埋め込み、H.264/H.265などの標準的な動画圧縮技術を活用して、コンパクトなMP4ファイルに大量のテキストデータを格納するというものです。

**技術的な詳細**

開発者によると、10,000個のPDFを1.4GBの動画ファイルに圧縮し、検索レイテンシは約900ms（Pineconeの820msと比較して約10%遅い程度）を実現したとのことです。

内部的には、sentence-transformersを使った埋め込み生成、FAISSによる効率的な類似度検索、OpenCVによる動画処理を組み合わせています。

**主な特徴と利点**

従来のベクトルデータベースと比較して、最大10倍の圧縮率、サブ秒での検索、オフライン対応、ポータビリティの高さなどが謳われています。

**懐疑的な意見も**

Hacker Newsでは一部のユーザーから「これはトロールなのでは」という懐疑的な意見も見られましたが、実際に動作するコードとライブラリが公開されているため、少なくとも概念実証としては機能しているようです。

**結論**

基本的な主張は本当で、実際に動作するライブラリです。ただし、「革命的」という表現については、実際の性能や実用性を慎重に評価する必要があります。

### LLMに引用されやすいページの特徴 (2025.11.08)

📘 LLMに引用されやすいページの特徴（Ahrefs分析）

- よくある質問に明確に答えている → 具体的な問いに即答できる構成が重要。例：「○○の費用はいくら？」
    
- 更新日（タイムスタンプ）が明示されている → LLMは最新性のあるページを優先的に参照する傾向がある。
    
- 専門家の著者名や肩書きが明記されている → 出典としての信頼性をAIが判断しやすくなる。
    
- 独自データ・調査に基づいている → 他サイトとの差別化が明確になり、AIが"引用価値"を認識する。
    
- 冒頭に結論と要点整理がある → スキャン性が高く、AIが内容を抽出しやすい。
    
- 内容が具体的で実務に使える → 抽象論よりも数値・事例・手順などの具体性が評価される。
    
- 多角的なデータでトピックを網羅している → 比較・表・グラフなどを用い、幅広くカバーしているページが好まれる。

### 中国で機能するVPN (2025.11.17)

**推奨方法まとめ**

- **国際データプランとホットスポットの活用** (@liudotblog):
    
    - 最も信頼できる方法として、外国キャリアの国際データプランを取得し、ホットスポットとしてすべてを接続することを推奨。
    - 理由: 国際モバイルデータはファイアウォールにかからないため。
- **Three HK eSIMの使用** (@0xVasconcelos):
    
    - VPN不要で、Three HKのeSIM（中国データ対応）を入手し、必要に応じて通常のVPNを組み合わせる。
    - 「これ以上良いセットアップはない」と強調。
- **Astrill VPNの推奨** (@noelcetaSEO, @DagMalstaf):
    
    - 中国在住の兄弟からの情報としてAstrill VPNを推薦。
    - 中国の同僚からもhttps://www.astrill.com を推奨。
- **他の国のSIMカードの使用** (@fiteth_):
    
    - 香港やマレーシアなどの外国SIMカードが完璧に機能する。
- **自分のVPSを通したトンネリング** (@Marcia_Ong):
    
    - 自分のVPSを使ってトンネルを作成することを推奨。
- **Shadowsocks/x-ray/v2rayのセットアップ** (@tynervp):
    
    - VPS上でShadowsocks/x-ray/v2rayを5分以内でセットアップし、VPNより信頼性が高いと主張。

**全体の傾向と注意点**

- 多くのリプライがVPNアプリ単体ではなく、eSIMや国際SIM、VPSを組み合わせた方法を重視。中国のグレートファイアウォール対策として、IPブロックのリスクを避ける工夫が目立つ。
