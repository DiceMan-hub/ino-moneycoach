AI エージェントの Skills システムの深掘り解説
この X 投稿（@sora19ai のスレッド）は、AI エージェントの構築において「Skills」を重視するアプローチを提唱しており、特に Anthropic 社の Skills システムを基にしています。投稿の核心は、エージェントを直接作るのではなく、Skills をモジュール化して設計せよ、という点です。多くの人が Skills をごちゃ混ぜに扱いがちですが、それを 3 つのレイヤー（Foundational, Partner/Third-party, Enterprise）に分けることで、再現性が高く、効率的に回る仕組みが作れると主張しています。
この考え方は、引用されている YouTube 動画「Don’t Build Agents, Build Skills Instead – Barry Zhang & Mahesh…」 ￼（Anthropic の Barry Zhang と Mahesh による講演）から着想を得ており、動画では Skills を「最小限のポータブルなプロシージャル知識のパッケージ」と定義。エージェントは一般的な知能は持つものの、ドメイン特化の専門性が不足しがちで、Skills を動的にロードすることでそれを補う、というパラダイムシフトを説明しています。以下で、投稿の内容を基に動画の洞察を加えながら深く解説します。
全体の背景：なぜ「Agents ではなく Skills を作れ」なのか？
• エージェントの問題点: エージェントは「300IQ の天才数学者」のような汎用知能を持っていますが、税務や法律などの専門ドメインで一貫した実行が苦手。動画では、エージェントが専門知識を事前に吸収しにくく、学習を蓄積しにくい点を指摘。例えば、金融レポート作成では API 呼び出しや Python 分析が必要ですが、エージェント単体では毎回一から考え直すため非効率。
• Skills の利点: Skills はファイルのコレクション（スクリプト、メタデータ、指示書など）で構成され、シンプルで共有・バージョン管理しやすい（Git や Google Drive で扱える）。エージェントがランタイムで必要な Skills をロードし、組み合わせる（コンポーザブル）ことで、柔軟に専門性を付与。動画では、Skills のエコシステムが 5 週間で数千個に成長した例を挙げ、非技術者（財務や人事担当者）でも作成可能と強調。
• MCP（Model Communication Protocol）との連携: Skills は外部接続を扱う MCP サーバーと補完関係。Skills が専門知識を提供し、MCP がワークフローをオーケストレート。例えば、ブラウザ操作や Notion 検索を Skills で標準化。
• 未来像: Skills はソフトウェアのように進化（テスト、評価、バージョン管理、依存関係）。エージェントが Skills を作成する「Skill Creator Skill」も可能で、学習を共有可能な「記憶」として蓄積。
投稿では、この Skills を 3 レイヤーに分ける重要性を強調。ごちゃ混ぜにすると設計がブレ、再現性が失われる。動画もこの 3 タイプを明確に分類し、誰でも作成・消費可能と述べています。以下で各レイヤーを詳しく。

1. Foundational Skills（基礎スキル）
   • 投稿の説明: 思考の「手順書」を固定する層。モデルを賢くするのではなく、人間が毎回バラバラにやる思考プロセスを標準化。例えば：
   • アイデア出し: 「前提を疑う」「極端なケースから考える」などで発散重視。
   • 戦略決め: 「ゴールから逆算」「今やる一手」まで落とす。
   • 経験活用: 過去の失敗パターンや得意/苦手を前提に提案。 これを Skills に埋め込むと、再現性が高まる。
   • 動画の補完と例: 一般的な能力やドメイン特化の基盤を提供。エージェントに新しいケイパビリティを付与する。
   • Anthropic のドキュメントスキル: Claude がプロ品質のオフィスドキュメントを作成・編集（例: スライドのスタイリングを Python スクリプトで固定）。
   • Cadence の科学リサーチスキル: EHR データ分析や Python バイオインフォマティクスライブラリ活用。
   • なぜ重要か?: 誰が使っても最低ラインの品質を確保。動画では、メタデータで Skills の存在を示し、必要時のみフルロードしてコンテキストウィンドウを効率化（数百の Skills を扱える）。
   • 設計 Tips: 思考モードを先に揃え、「誰が使っても最低ラインは超える」状態を目指す。投稿の優先度で最初に作るべきレイヤー。
2. Partner / Third-party Skills（パートナー/サードパーティスキル）
   • 投稿の説明: ツールの使い方を固定。各ツールに共通の「触り方」を作る。例えば Notion 系: 情報の場所・粒度・整理ルールをスキル化。ポイントは、ツールごとの「思考インターフェース」を統一し、エージェントが一貫して扱えるようにする。
   • 動画の補完と例: エコシステムパートナーによる製品強化。外部ツールの専門性を注入。
   • Browserbase のスキル: オープンソースブラウザ自動化ツール（Stagehand）で、Claude がウェブナビゲーションを効果的に。
   • Notion のスキル: ワークスペースの深い理解とリサーチ（例: データの場所を標準化し、検索を効率化）。
   • なぜ重要か?: SaaS ツールをエージェントが自然に活用可能に。動画では、従来のツールの問題（曖昧な指示、非修正性、コンテキスト clutter）を解決。Skills は自己文書化され、修正可能で、ファイルベースなので柔軟。
   • 設計 Tips: Foundational の後で作り、各種 SaaS を実行可能に。投稿では、ツールの「共通の触り方」を強調し、インターフェースの揃え方をコアに。
3. Enterprise Skills（エンタープライズスキル）
   • 投稿の説明: 組織だけの「勝ちパターン」を固める。最重要で、再現不能な固有資産。内容は 3 レイヤー:
   • ポリシー: 機密区分、許可ツール、承認フロー。
   • 業務フロー: 営業プロセス、CS 対応、開発チケット。
   • ベストプラクティス: 条件ごとの選択、失敗回避策。 コアは「ルール → 手順 → 判断基準 → 例外処理」を束ねること。
   • 動画の補完と例: 企業・チーム特化で、内部ベストプラクティスやソフトウェア使い方を教える。Fortune 100 企業や大規模開発チームで活用（数千〜数万人の開発者向け）。
   • 例: 財務、採用、会計、法律のプロセス嵌入。コードスタイルガイドラインや独自ツールの扱い。
   • なぜ重要か?: 差別化ポイント。動画では、Skills が組織の知識をエンコードし、共有可能。非技術者も作成し、垂直市場（金融、ライフサイエンス）で迅速展開。
   • 設計 Tips: 最後に作り、組織の「勝ち方」を埋め込む。投稿では、このレイヤーで差別化を強調。
   3 種類の優先度と実践アドバイス
   • 投稿の推奨順: 1. Foundational → 思考モードを揃え、最低品質確保。 2. Partner/Third-party → SaaS 実行可能に。 3. Enterprise → 差別化。 これで設計がブレず、本当に回るエージェントに。Claude for Chrome のブラウザ操作を Skills でブーストせよ、とアドバイス。
   • 動画の洞察: Skills は複雑化中（プロンプトからスクリプト/資産へ）。エージェントアーキテクチャ: 一般エージェント + ランタイム（ファイルシステム） + MCP + Skills ライブラリ。非技術者向けアクセシビリティが高く、コミュニティで進化。
   • なぜ分けるか?: ごちゃ混ぜだと、再現性が失われ、デモ止まり。レイヤー分けでスケーラブルに。動画では、Skills が「アプリケーション」のような役割を果たし、モデル（プロセッサ）とランタイム（OS）を補完。
   まとめと実践のヒント
   このアプローチは、2026 年の AI トレンド（投稿の「置いて行かれたくない人は全員見たほうがいい」）を象徴。エージェントは汎用、Skills は専門性をモジュール化し、組み合わせで強力に。動画では、Skills が連続学習を可能にし、コミュニティ知識ベースを形成するとビジョン化。
   実践: 自分の現場で「どのレイヤーからスキル化するか」を決め、シンプルなファイルからスタート（例: Markdown + スクリプト）。Anthropic の Cloud Agent SDK や Dify（投稿作者の専門）で試すと良い。興味があれば、動画視聴をおすすめします。 ￼
