# 世界でよく使われている「AIの文脈・記憶を残す」方法

**目的**: Claude Code などはセッションごとに記憶がリセットされる。コンテキストを永続化する方法のうち、世界で広く使われているものをまとめる。

---

## 1. 公式・組み込み

### Memory.md（公式・「これ覚えておいて！」で書き込まれる記憶）

- **概要**: Claude Code の**新機能**。セッションをまたいで「これ覚えておいて！」「これ記憶しておいて！」と指示すると、Claude が自動で Memory.md に書き込んでくれる。**ユーザーが何も言わなくても**、会話中の有用な情報を検知して MEMORY.md やトピック別ファイル（例: `debugging.md`）に逐次保存することもある（Tariq 氏の説明より）。
- **保存場所**: **プロジェクトフォルダ外**。`~/.claude/projects/<あなたのプロジェクト>/memory/Memory.md`（Claude Code の「会話プロジェクト」内）。
- **役割の分け方**: **CLAUDE.md = ルール特化**、**Memory.md = その他の記憶特化**。プロジェクトごとに独立（他プロジェクトに影響しない）。
- **参照**: [AI駆動塾 @L_go_mrk の紹介](https://x.com/l_go_mrk/status/2027212536362447346)、[マジで世界一やさしいClaudeCodeの教科書 完全版](https://note.com/l_mrk/n/n435e046b6a67)

### Claude Code の Session Memory（公式・要約の自動保存）

- **概要**: Claude Code に**標準で入っている**セッション記憶。設定不要で動く。
- **動き**: セッション中に約 5,000 トークンごと（またはツール呼び出し 3 回ごと）に要約を抽出し、`summary.md` に保存。新規セッション開始時に「Recalled X memories」として読み込む。
- **保存場所**: `~/.claude/projects/<project-hash>/<session-id>/session-memory/summary.md`
- **内容例**: セッションタイトル、現在の状態、タスク仕様、重要ファイル・関数、ワークフロー、エラーと修正、学び、結果・決定、作業ログなど。
- **確認**: 起動時に「Recalled X memories」と出たら `ctrl+o` で内容を展開できる。ファイルは Markdown なので編集・削除可能。
- **参照**: [Anthropic Docs - Manage Claude's memory](https://docs.anthropic.com/en/docs/claude-code/memory)、[Claude Code Session Memory 解説](https://claudefa.st/blog/guide/mechanics/session-memory)

**注意**: Session Memory も Memory.md も「セッション間の参照用」。自分で設計した判断基準・嗜好を**確実に毎回読ませる**には、CLAUDE.md や .cursor/context/ のような**プロジェクト内のファイル**と組み合わせるのが確実。

## 2. サードパーティ（ツール・プラグイン）

### Claude-Mem（Claude Code 専用・人気）

- **概要**: Claude Code 用の**永続メモリプラグイン**。オープンソース、ローカル（SQLite）保存。
- **機能**: ツール利用を自動キャプチャ → Claude Agent SDK で意味的な要約を生成 → 過去セッションのコンテキストを次回セッションに注入。約 10 倍のコンテキスト圧縮。
- **導入**: Claude Code 内で  
  `/plugin marketplace add thedotmack/claude-mem`  
  `/plugin install claude-mem`  
  再起動後、過去セッションの文脈が自動で出る。
- **その他**: FTS5 全文検索、Web UI（http://localhost:37777）、MCP 検索ツール、`<no-mem>` で機密を記憶から除外、フォルダごとに CLAUDE.md を自動生成する機能あり。
- **要件**: SQLite3、Bun（未導入なら自動）、Node.js 18+、Claude Code（プラグイン対応版）。
- **参照**: https://docs.claude-mem.ai/

### Recallium（Cursor / Claude / VS Code / Copilot 対応）

- **概要**: コーディングエージェント向け**AI メモリ**。**MCP（Model Context Protocol）** で接続。5,000+ 開発者が利用。
- **機能**: 決定・パターン・ソリューションをプロジェクト／セッションをまたいで永続化。自動キャプチャ＋ハイブリッド検索（約 88% の first-result 精度）。ダッシュボードでメモリ・トークン利用を分析。
- **導入**: 自社ホスト・無料（Ollama + 組み込み embeddings）。  
  `cd install && ./start-recallium.sh`（Mac/Linux）など → `http://localhost:9001` でセットアップ。MCP で Cursor / Claude に接続。
- **使い方**: 「この JWT 実装を記憶して」のように指示すると記憶。IDE で「recallium」と打つとプロジェクトコンテキストを一括読み込み。16 個の MCP ツール。
- **参照**: https://recallium.ai/、https://www.recallium.ai/setup

### ContextStream

- **概要**: AI ツール向けの**永続メモリ**。意味的コード検索・ナレッジグラフ。Cursor / Claude Code など MCP 対応ツールと連携。
- **機能**: 6 種類の検索（semantic, hybrid, symbol, refactor, pattern, exhaustive）、コンテキストのフィルタ・重複除去でトークン節約。
- **参照**: https://contextstream.io/

### CogmemAi（クラウド）

- **概要**: クラウド型の永続メモリ。セマンティック検索でセッション開始時に関連記憶を自動ロード。
- **導入**: `npx cogmemai-mcp setup` のみ。MEMORY.md の手動メンテを減らし、セッションあたり約 2,250 トークン節約をうたう。

## 3. 手動・ファイルベース（いまの .cursor/context/ のやり方）

- **CLAUDE.md**: プロジェクトルートの共有コンテキスト。Claude Code が最初に読む。
- **~/.claude/CLAUDE.md**: ユーザー全体のデフォルト（全プロジェクト共通）。
- **Memory.md（公式）**: 上記「1. 公式」参照。`~/.claude/projects/<project>/memory/` に置かれる。「これ覚えておいて！」で自動書き込み＋会話中の有用情報を検知してトピック別ファイルにも保存。
- **プロジェクト内の Markdown（例: .cursor/context/）**: 判断基準・過去の結果・嗜好を自分で書き、CLAUDE.md から「ここを読め・ここに追記しろ」と指示する方式。ツール不要、**Git で管理・共有可能**。

## Memory.md（公式）と .cursor/context/ の違い

| 項目 | **Memory.md（公式）** | **.cursor/context/（いまの設定）** |
|------|------------------------|-------------------------------------|
| **場所** | `~/.claude/projects/<project>/memory/`（リポジトリ外） | リポジトリ内 `.cursor/context/` |
| **書き込み** | 「これ覚えておいて！」で Claude が**自動**で書く。会話中の有用情報を**検知して自動**で MEMORY.md や debugging.md 等にも逐次保存 | 「記録して」「contextに残して」など**ユーザーが促す**か、AI が追記案を出して**了承されたら**書き込む（明示的） |
| **構造** | 1 本の Memory.md ＋ トピック別ファイル（例: debugging.md）。Claude が中身を決める | 01 判断基準 / 02 過去の結果 / 03 嗜好 の**3ファイルで設計**。人間が項目を決める |
| **Git** | 通常は .claude はリポジトリに含めない → **個人のローカルのみ**、共有・バックアップは別手段 | リポジトリに含める → **Git で履歴・共有・バックアップ**可能 |
| **Cursor** | Claude Code のプロジェクト記憶なので **Claude Code 専用** | CLAUDE.md と .cursorrules の両方から参照する設計なので **Claude Code と Cursor の両方**で同じ文脈を使える |
| **向き** | 「とにかく覚えてもらえればいい」を**手軽に・自動で**やりたいとき。ルールは CLAUDE.md、その他は Memory に任せる | 「判断基準・嗜好・過去の結果」を**自分で設計して確実に毎回読ませたい**とき。Git で育ててチームや別環境でも同じ文脈を使いたいとき |

**併用**: Memory.md で日々の「覚えておいて」を自動蓄積しつつ、.cursor/context/ で**核となる判断基準・嗜好**をリポジトリ側に持っておく、という使い分けが現実的。

## まとめ：どれを選ぶか

| 方法 | 向き |
|------|------|
| **Memory.md（公式）** | 「これ覚えておいて！」で**自動**書き込み。CLAUDE.md はルール、Memory はその他の記憶。手軽で素敵。 |
| **Session Memory（公式）** | まずは標準のまま使う。セッション間の「何をやっていたか」の継続には有効。 |
| **Claude-Mem** | Claude Code を主に使い、**自動でツール利用まで圧縮して残したい**場合。プラグイン 1 本で完結。 |
| **Recallium** | Cursor / Claude / VS Code をまたいで**チームや複数プロジェクトで記憶を共有**したい場合。MCP で統一。 |
| **ファイルベース（.cursor/context/）** | 「判断基準・嗜好・過去の結果」を**自分で設計して確実に毎回読ませたい**場合。Git で共有したい場合。ツールに依存しない。 |

**併用**: Memory.md（公式）で「覚えておいて」を自動蓄積 ＋ .cursor/context/ で核となる判断基準・嗜好をリポジトリに持つ、が現実的。  
さらに「ツールの自動キャプチャ」が欲しければ Claude-Mem や Recallium を足す。
