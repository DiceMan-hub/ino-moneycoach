## Skill 1: `/client-assessment`（顧客ポートフォリオ診断）

### 入力データ構造

```yaml
client:
  name: "株式会社ABC"
  industry: "飲食業"           # 業種コード or フリーテキスト
  entity_type: "法人"          # 法人 / 個人事業主
  established: 2015
  fiscal_month: 3
  employees: 8

financials:                     # 直近3年
  - year: 2025
    revenue: 85000000
    expenses: 78000000
    income: 7000000
  - year: 2024
    revenue: 72000000
    ...

current_contract:
  monthly_fee: 30000
  services: ["記帳代行", "申告"]
  bookkeeping: "full"           # full / partial / self
  monthly_entries: 150
  meeting_frequency: "annual"   # monthly / quarterly / semi / annual

qualitative:
  communication: "good"         # good / normal / difficult
  responsiveness: "slow"        # fast / normal / slow
  interests: ["節税", "融資"]
  trouble_history: null
  succession_need: false
  referral_potential: "medium"  # high / medium / low
```

### スコアリングロジック（各10点、合計100点）

```
1. 売上規模（= 将来の顧問料成長余地）
   1億超→10 / 5000万超→7 / 1000万超→4 / 500万超→2 / 以下→1

2. 顧問料の妥当性（= 今の利益率）★最重要
   推定工数 = f(仕訳数, 記帳有無, 申告の複雑度)
   時間単価 = 年間顧問料 ÷ 推定年間工数
   8,000円/h超→10 / 5,000超→7 / 3,000超→5 / 3,000未満→2

   推定工数の計算:
     記帳代行(full): 仕訳数×3分 + 月次チェック60分 = 月の工数
     記帳代行(partial): 仕訳数×1.5分 + 月次チェック45分
     自計化(self): 月次チェック30分のみ
     決算・申告: 法人20h / 個人8h（年1回）
     年末調整: 従業員数×30分（年1回）

3. 業種親和性
   得意業種リストに一致→10 / 経験あり→5 / 未経験→2
   デフォルト: 全業種5（事務所が設定するまでニュートラル）

4. 記帳負荷（= 工数の重さ）
   自計化→10 / 一部代行→5 / 全部代行→2
   ※仕訳数で補正: 300件超/月→-2点

5. 成長性
   3年CAGR: 10%超→10 / 5%超→7 / 0%超→5 / マイナス→2
   データ不足（1年分のみ）→ 5（ニュートラル）

6. M&A・事業承継可能性
   succession_need=true → 10
   代表年齢65歳以上（推定 or 入力）→ 7
   interests に「承継」「M&A」→ 7
   それ以外 → 3

7. コミュニケーション品質
   communication=good + responsiveness=fast → 10
   good + normal → 8
   normal + normal → 5
   difficult or slow → 2
   trouble_history あり → -3点（最低1点）

8. アップセル余地
   interests の数 × 3（最大10）
   interests が空 → 2
   ※法人化未実施の個人事業主で所得500万超 → +3ボーナス

9. 紹介可能性
   referral_potential: high→10 / medium→5 / low→2
   ※業種が「士業」「不動産」「保険」→ +2（紹介が多い業種）

10. リスク
    trouble_history なし + 経費率が業種平均内 → 10
    trouble_history あり → 4
    経費率が業種平均の1.3倍超 → -3
    税務調査履歴あり（直近3年）→ 3
```

### ティア分類ロジック

```
S: 80点以上
A: 60-79点
B: 40-59点
C: 39点以下

強制ルール（スコアに関係なく上書き）:
  - 時間単価2,000円未満 → 最大でもB
  - trouble_history + communication=difficult → 最大でもC
  - 売上1億超 + 成長中 → 最低でもA
```

### 出力

```
1. 全社ティア一覧（ソート: S→C、同ティア内は時間単価降順）
2. ティア別集計: 社数、合計顧問料、合計推定工数、平均時間単価
3. 担当アサイン案: ティア×既存担当者のキャパから自動提案
4. 赤字顧客フラグ: 時間単価3,000円未満のリスト
5. 顧問料改定提案: 現顧問料と「適正顧問料」の差分リスト
6. 顧客別オンボーディングチェックリスト
```

## Skill 2: `/tax-diagnostic`（税務ヘルスチェック報告書）

### 入力データ構造

```yaml
client_type: "個人事業主"       # 法人 / 個人事業主
industry: "IT・クリエイター"
filing: "青色申告"              # 青色 / 白色

income:
  business_income: 8000000
  salary_income: 0
  real_estate_income: 0
  dividend_income: 50000
  capital_gains: 200000
  misc_income: 0

deductions_current:
  basic: 480000
  social_insurance: 400000
  ideco: 0
  small_business_mutual: 0
  life_insurance: 50000
  earthquake_insurance: 0
  medical: 0
  furusato: 30000
  spouse: 0
  dependent: 0
  blue_form_special: 650000

expenses:
  home_office_ratio: 0.3
  home_rent: 100000
  utilities: 15000
  communication: 12000
  depreciation_assets: []

family:
  spouse: true
  spouse_income: 0
  dependents: 1

consumption_tax:
  taxable_revenue: 8000000
  status: "免税"                # 免税 / 簡易 / 本則
  invoice_registered: false
```

### 診断ロジック（12チェック項目）

```
■ 所得控除の漏れスキャン

Check 1: 小規模企業共済
  条件: small_business_mutual == 0 AND (entity=個人事業主 OR entity=法人役員)
  判定: 「未加入」→ 推奨
  効果額: 所得税率 × 840,000（満額の場合）

Check 2: 経営セーフティ共済
  条件: 経費に「倒産防止共済」がない AND 事業所得 > 0
  判定: 「未加入」→ 推奨（事業開始1年以上が条件）
  効果額: 最大2,400,000/年の経費計上

Check 3: iDeCo
  条件: ideco == 0 OR ideco < 上限額
  上限判定:
    第1号被保険者（個人事業主）→ 月68,000円（年816,000円）
    第2号被保険者（会社員）→ 月23,000円（年276,000円）
  効果額: (上限 - 現在の掛金) × 所得税率

Check 4: ふるさと納税の最適額
  計算:
    課税所得 = 総所得 - 所得控除合計
    所得税率 = 累進税率テーブルから取得
    住民税所得割 = (総所得 - 所得控除) × 10%
    上限額 ≈ 住民税所得割 × 20% ÷ (1 - 所得税率 × 1.021 - 0.1) + 2,000
  判定: furusato < 上限額 × 0.9 → 「余裕あり」

Check 5: 配偶者控除
  条件: spouse == true AND spouse_income <= 480,000 AND 控除なし
  効果額: 380,000 × 所得税率

Check 6: 医療費控除
  条件: medical == 0
  判定: ヒアリング項目「年間医療費が10万円を超えていませんか？」

Check 7: 生命保険料控除
  条件: life_insurance < 120,000
  判定: 「枠が余っている」

Check 8: 青色65万控除の要件
  条件: blue_form_special < 650,000
  判定: 簡易簿記→複式簿記+e-Tax推奨

■ 法人化シミュレーション（個人事業主のみ）

Check 9: 法人化判定
  条件: entity=個人事業主 AND business_income > 5,000,000
  計算:
    【個人】所得税+住民税+事業税+国保 = A
    【法人】法人税等+役員報酬の所得税住民税+社保 = B
    差額 = A - B → 正なら法人化推奨

■ 経費チェック

Check 10: 家事按分の妥当性
  按分率 < 業種標準の下限 → 「低すぎる可能性」
  標準値: IT/クリエイター→30-50% / 営業→20-40% / 店舗型→10-20%

Check 11: 少額減価償却
  条件: 青色申告者 → ヒアリング項目

■ 消費税

Check 12: 簡易 vs 本則 + 2割特例
  条件: status != "免税"
  みなし仕入率 = 業種別テーブル
  安い方を推奨 / 2割特例の適用可否判定
```

### 出力

```
顧客向けレポート（PDF、3ページ）:
  - 発見事項 TOP5（効果額降順）
  - 各項目: 施策名 / 推定年間効果額 / 実行難易度 / 備考
  - 合計推定節税額
  - 免責文言

社内用メモ:
  - 全12項目のチェック結果
  - 面談で話すべきポイント
  - アップセル機会（法人化・経営支援等）
```

## Skill 3: `/tax-qa`（税務Q&Aアシスタント）

### 入力

```yaml
question: "取材で泊まったホテル代は経費になりますか？"
client_context:  # 自動付与
  name: "田中太郎"
  entity: "個人事業主"
  industry: "クリエイター"
  revenue_range: "500-1000万"
  filing: "青色"
```

### 処理フロー

```
Step 1: 質問の分類
  カテゴリ判定: 経費判定 / 控除相談 / 届出手続き / 法人化相談 /
               消費税 / 給与計算 / 年末調整 / 確定申告 /
               資産税（相続・贈与）/ その他
  緊急度: 期限あり→高 / 金額大→高 / 一般→通常

Step 2: ナレッジ検索（RAG、優先順）
  1. 事務所の過去Q&A
  2. 事務所の判断基準メモ（社長のポリシー）
  3. 国税庁タックスアンサー
  4. 主要な通達・質疑応答事例
  5. LLMの一般知識（最終手段）

Step 3: 回答生成
  ① 結論（1行）
  ② 理由（根拠条文 or 通達）
  ③ 顧客向け説明文（そのまま送れる文面）
  ④ 注意点
  ⑤ 関連情報

Step 4: 確信度判定
  過去Q&Aに完全一致 → 高
  タックスアンサーに明確な記載 → 高
  通達レベルで根拠あり → 中
  解釈が分かれる / 個別事情依存 → 低
  ソースなし → 低

  アクション指示:
    高 → ジュニアがそのまま回答可
    中 → シニアの確認を推奨
    低 → 社長判断が必須
```

### ナレッジ蓄積ループ

```
質問 → Agent回答（ドラフト）→ 税理士レビュー
  ├── そのまま承認 → ナレッジDBに登録（確信度:高）
  ├── 修正して承認 → 修正版を登録 + 修正点を学習
  └── 却下 → 正しい回答を登録 + エラーパターン記録

→ DBが育つほど: ヒット率UP / 確信度「高」の比率UP / 社長負荷DOWN
```

### 事務所カスタマイズ層

```yaml
policy:
  expense_stance: "moderate"     # conservative / moderate / aggressive
  incorporation_threshold: 5000000
  tone: "professional"           # professional / friendly / brief
  disclaimer: "本回答は一般的な税務情報の提供を目的としており..."

knowledge_base:
  custom_qa: "./qa_database.json"
  boss_notes: "./policy_notes.md"
```

## 3つの連携ロジック

```
/client-assessment → /tax-diagnostic
  ティアS/A → 詳細版（全12項目）
  ティアB/C → 簡易版（控除漏れ + 法人化判定のみ）

/tax-diagnostic → /tax-qa
  診断結果を顧客コンテキストに追加
  例:「この顧客は小規模企業共済未加入」→ 関連質問に即答

/tax-qa → /client-assessment
  Q&A頻度 → コミュニケーション品質スコアに反映
  高度な質問 → アップセル余地スコアに加点
```
