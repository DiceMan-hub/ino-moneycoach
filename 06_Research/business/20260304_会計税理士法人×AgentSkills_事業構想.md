# 会計税理士法人 × AI Agent Skills：事業構想メモ

> **作成日**: 2026-03-04
> **目的**: 税務最適化プロンプト集を、会計税理士法人がAgent Skillsとして実装・提供するビジネスモデルの探索
> **ステータス**: 初期構想

---

## 1. 前提整理：税理士業務の構造

### 税理士法人の業務と課題

| 業務カテゴリ | 具体的な作業 | 現状の課題 |
|------------|------------|----------|
| **記帳代行** | 仕訳入力、帳簿作成 | 単価低い、人手がかかる、AIで置換されつつある |
| **確定申告・決算** | 申告書作成、決算書作成 | 繁忙期に集中、3月は地獄 |
| **税務相談** | 節税提案、法人化判断、事業承継 | **高単価だが属人的**。シニア税理士しかできない |
| **税務調査対応** | 調査立会い、意見書作成 | 経験値に依存。若手が育たない |
| **年末調整・給与計算** | 従業員の年調、源泉徴収 | 定型だがボリュームが大きい |
| **コンサルティング** | 事業承継、M&A税務、国際税務 | **最高単価。しかし人材不足** |

### 業界の構造的問題

1. **属人化**: 税務判断はベテランの頭の中にある → スケールしない
2. **繁忙期偏重**: 11月〜3月に業務集中 → 年間の稼働が非効率
3. **単価下落**: 記帳代行・申告代行はfreee/マネフォに侵食されている
4. **顧問先との接点不足**: 年1回の申告だけの関係 → LTVが低い
5. **若手不足**: 税理士試験の受験者減少、業界の高齢化

### Agent Skillsが解決できるポイント

**「シニア税理士の判断力を型化し、ジュニアでも高品質な提案ができるようにする」**

→ これが最大の価値。記帳代行のAI化ではなく、**コンサル領域のスケール化**。

## 3. Agent Skillsのアーキテクチャ構想

### 3つのレイヤー

```
┌─────────────────────────────────────────────┐
│  Layer 3: クライアント向けセルフサービス       │
│  （税務診断、ふるさと納税計算、簡易シミュレーション）│
├─────────────────────────────────────────────┤
│  Layer 2: 税理士の提案作成支援                │
│  （節税提案書、法人化シミュレーション、年末レビュー）│
├─────────────────────────────────────────────┤
│  Layer 1: 社内ナレッジ・判断支援              │
│  （税法検索、判例参照、調査対策ノウハウ）         │
└─────────────────────────────────────────────┘
```

### Layer 1: 社内ナレッジ・判断支援（内部ツール）

**目的**: 税理士の判断をサポート。社内で使うAgent。

| Skill名 | 機能 | 入力 | 出力 |
|---------|------|------|------|
| `/tax-law-search` | 税法・通達・判例の検索 | キーワード or 相談内容 | 関連条文・通達・判例の要約 |
| `/audit-prep` | 税務調査の論点整理 | 申告書の概要 | 指摘されやすいポイントと反論材料 |
| `/entity-compare` | 個人vs法人の税負担比較 | 売上・経費・家族構成 | 比較表と損益分岐点 |
| `/tax-calendar` | 税務カレンダー生成 | 顧問先のプロフィール | 年間の申告・届出期限一覧 |

**実装のポイント**:
- 税法データベース（e-Gov法令API、国税庁タックスアンサー）をRAGで接続
- 事務所内の過去案件（匿名化）を学習データに
- 「AIが出した回答 → 税理士がレビュー → 承認」のワークフロー必須

### Layer 2: 税理士の提案作成支援（生産性ツール）

**目的**: 税理士が顧問先に出す提案書・レポートのドラフトを自動生成。

| Skill名 | 機能 | 入力 | 出力 |
|---------|------|------|------|
| `/tax-diagnostic` | 税務ヘルスチェック報告書 | 顧問先の申告データ | 診断レポート（PDF） |
| `/optimization-proposal` | 節税提案書 | 所得・控除・家族構成 | 施策一覧と効果額 |
| `/yearend-review` | 年末レビューレポート | 1-11月の実績データ | 12月アクション一覧 |
| `/multi-year-plan` | 3-5年タックスプラン | 顧問先の中期計画 | 年度別ロードマップ |
| `/furusato-calc` | ふるさと納税上限計算 | 所得・控除の見込み | 最適額と寄附計画 |

**実装のポイント**:
- 会計ソフト（freee / マネフォ / 弥生）のAPIから数字を自動取得
- 事務所のブランドでPDF出力（ロゴ・フォーマット統一）
- 「下書き → 税理士の確認・修正 → 顧問先に送付」のフロー

### Layer 3: クライアント向けセルフサービス（集客ツール）

**目的**: 見込み客の獲得、既存顧問先の満足度向上。

| Skill名 | 機能 | 入力 | 出力 |
|---------|------|------|------|
| `/free-diagnostic` | 無料の税務簡易診断 | Webフォームで基本情報 | 診断結果＋「詳細は面談で」 |
| `/simulator` | 法人化シミュレーター | 売上・経費を入力 | 個人vs法人の比較 |
| `/furusato-tool` | ふるさと納税計算ツール | 年収・控除を入力 | 上限額と推奨プラン |
| `/checklist` | 確定申告準備チェックリスト | 業種・所得区分を選択 | 必要書類一覧 |

**実装のポイント**:
- 事務所のWebサイトに埋め込み（チャットボットUI or フォーム型）
- **無料 → 診断結果で課題を提示 → 「この先は顧問契約で」** のリード獲得導線
- 個人情報の取り扱いに注意（プライバシーポリシー必須）

## 4. ビジネスモデルの選択肢

### A案：税理士法人が自社で内製

```
対象: IT力のある中〜大規模法人（職員30人以上）
投資: 初期開発500-1000万 + 運用月20-50万
回収: 生産性向上（提案書作成時間50%削減）＋新規顧問獲得
```

- メリット：自社のノウハウが蓄積、差別化
- デメリット：開発・維持コスト、IT人材が必要

### B案：SaaS として複数の税理士事務所に提供

```
対象: 全国の税理士事務所（約3.3万事務所）
価格: 月額3-10万円/事務所（機能レベルで段階制）
- Basic: Layer 1（税法検索・カレンダー）= 月3万
- Pro: Layer 1+2（提案書生成）= 月7万
- Enterprise: 全機能+カスタマイズ = 月15万
市場規模: 3.3万事務所 × 普及率5% × 月7万 = 年間約14億円
```

- メリット：スケーラブル、継続収益
- デメリット：税理士業界はIT導入に保守的、営業コスト

### C案：税理士法人 + SaaS のハイブリッド

```
自社事務所でAgentを活用して高効率経営（A案）
＋
そのシステムを他事務所にもライセンス提供（B案）
```

- **実はこれが最も現実的**
- 自社で使って磨く → 実績を見せて外販
- 「このシステムを使っている事務所」というブランディング

### D案：顧問先向けポータルとして提供

```
対象: 税理士法人の顧問先（事業者・個人）
価格: 顧問料に含める or 月額3,000-5,000円のオプション
提供: 自社の顧問先専用ポータル（税務Q&A、シミュレーター、書類管理）
```

- メリット：顧問料の値上げ根拠、解約防止（ロックイン）
- デメリット：顧問先のITリテラシーに依存

## 5. 実装の技術スタック案

### 最小構成（MVP）

```
フロントエンド: Webフォーム（Next.js or Streamlit）
AI: Claude API（Opus/Sonnet）
データ:
  - 税法DB: 国税庁タックスアンサー + e-Gov法令APIをRAG化
  - 顧問先データ: 会計ソフトAPI連携 or CSV取込
出力: Markdown → PDF変換（提案書）
認証: 事務所アカウント管理
```

### フル構成

```
フロントエンド: 顧問先ポータル（Next.js）+ 社内ダッシュボード
AI: Claude API + RAG（税法・判例・通達のベクトルDB）
データ連携:
  - freee API / マネフォ API / 弥生 API
  - e-Tax連携（将来）
  - 国税庁RSS（税制改正速報）
ワークフロー:
  - Agent出力 → 税理士レビューキュー → 承認 → 顧問先配信
セキュリティ:
  - SOC2 or ISMS認証
  - 顧問先データの暗号化・分離
  - 税理士法の守秘義務との整合性
```

## 6. 法的・倫理的な論点

### 税理士法との関係

| 論点 | リスク | 対策 |
|------|--------|------|
| **AIが税務相談に回答** = 税理士法違反？ | 税理士法第52条「税理士でない者は税務相談をしてはならない」 | AIは「下書き・参考情報」であり、**最終判断は税理士が行う**建付けにする |
| **クライアント向けセルフサービス** | 「税務相談」に該当する可能性 | 「一般的な情報提供」「シミュレーション」に留め、「個別の税務判断は税理士にご相談ください」の免責を明記 |
| **他事務所へのSaaS提供** | 利用事務所側に税理士がいれば問題なし | 利用規約で「税理士資格保有者のいる事務所のみ」に限定 |

### データセキュリティ

- 顧問先の財務データは**最高レベルの個人情報**
- クラウドに送信する場合、顧問先の同意が必須
- APIに送信するデータの匿名化・最小化の設計が重要

## 7. 競合・既存プレイヤー

| サービス | 提供内容 | ポジション |
|---------|---------|----------|
| freee / マネフォ / 弥生 | 会計ソフト＋AI仕訳 | **記帳代行の代替**。コンサル領域は未踏 |
| ChatGPT / Claude（汎用） | 税務質問に回答 | 汎用すぎ。日本税制の精度に不安 |
| 税理士ドットコム | 税理士マッチング | プラットフォーム。ツール提供ではない |
| Cellsドライブ | 年末調整クラウド | 特定業務特化 |
| **空白地帯** | **税務コンサルのAIアシスタント** | **← ここが狙い目** |

**核心**: 記帳・申告はfreee等が攻めている。**「税務判断・提案」の領域はまだAI化されていない**。ここにAgent Skillsを投入する。

## 8. Go-to-Market 戦略案

### Phase 1: プロトタイプ（1-2ヶ月）

- 最も価値の高い3つのSkillをMVPとして開発
  1. `/tax-diagnostic`（税務ヘルスチェック）→ リード獲得
  2. `/optimization-proposal`（節税提案書）→ 提案効率化
  3. `/yearend-review`（年末レビュー）→ 顧問先フォロー
- 1つの協力税理士法人で実証

### Phase 2: 検証（3-6ヶ月）

- 協力法人での効果測定
  - 提案書作成時間の削減率
  - 新規顧問獲得数の変化
  - 顧問先の満足度変化
- フィードバックを元に改善

### Phase 3: 展開（6-12ヶ月）

- SaaS化して他事務所に展開
- 税理士向けセミナー・展示会でのプロモーション
  - 税理士会の研修 / 会計事務所EXPO / オンラインセミナー
- コンテンツマーケティング
  - 「AI活用で顧問先への提案力を10倍にする方法」等

## 9. 収益シミュレーション

### SaaSモデル（B案）の場合

| 年度 | 契約事務所数 | ARPU（月額） | MRR | ARR |
|------|------------|------------|-----|-----|
| Year 1 | 30 | 5万 | 150万 | 1,800万 |
| Year 2 | 100 | 6万 | 600万 | 7,200万 |
| Year 3 | 300 | 7万 | 2,100万 | 2.5億 |

前提:
- 全国税理士事務所 約3.3万のうち0.1%→0.3%→0.9%
- IT積極層（freee/マネフォ導入済み事務所）をターゲット
- 解約率: 月3%（年36%）→ 獲得ペースで上回る必要あり

### ハイブリッドモデル（C案）の場合

自社事務所の生産性向上:
- 税理士1人あたりの担当顧問先: 30社 → 50社（+67%）
- 提案書作成: 1件3時間 → 30分（-83%）
- 年末レビュー: 全顧問先に実施可能に（現状は上位20%のみ）

→ **売上増ではなく「利益率改善」と「サービス品質向上」が主効果**
