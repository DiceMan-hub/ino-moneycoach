# Claude Codeを組織導入するためのプラン選定ガイド（解説）

## 1. まず大前提：Anthropicの製品は「2つ」ある

記事の最初で重要なのはここです。

Anthropicのプロダクトは次の2つに分かれています。

|製品|用途|
|---|---|
|Claude|チャットUI / アプリ（人間が直接使う）|
|Claude Developer Platform|API（アプリやエージェントから使う）|

つまり

- ChatGPTのように使うClaude
    
- プログラムから呼び出すClaude
    

は**完全に別サービス**です。 ([Zenn](https://zenn.dev/knowledgework/articles/claude-code-organization-plan-guide?utm_source=chatgpt.com "Claude Codeを組織導入するためのプラン選定ガイド"))

さらに課金体系も違います。

|種類|課金|
|---|---|
|Claude|サブスク|
|Developer Platform|従量課金|

# 4. この記事の核心：AIエージェントのコスト思想

Knowledge Work社は  
AI導入の判断軸を**3つ**にしています。

### ①自由度

開発者が

- 新しいツール
    
- 新しいモデル
    

を自由に試せる状態。

理由

AIの進化は早すぎる。

制限すると

```
会社の競争力が落ちる
```

---

### ②支払い管理

会社として

- 誰が
    
- いくら
    
- 何を使った
    

を管理できる状態。

つまり

```
AIコストの可視化
```

---

### ③コスト制御

- 予算管理
    
- 利用制限
    
- 課金予測
    

---

## この3つの優先順位

記事でははっきり書いています。

```
自由度 > 支払い管理 > コスト
```

理由

AI開発では

```
ツール制限 = 生産性低下
```

になるから。 ([Zenn](https://zenn.dev/knowledgework/articles/claude-code-organization-plan-guide?utm_source=chatgpt.com "Claude Codeを組織導入するためのプラン選定ガイド"))

# 5. 組織導入で起きる典型問題

AIツール導入でよく起きるのはこれ。

### パターンA

```
コスト管理厳格
↓
ツール制限
↓
エンジニア不満
↓
使われない
```

---

### パターンB

```
自由に使わせる
↓
コスト爆発
↓
経理怒る
```

---

この記事の結論は

**自由度を優先して  
管理は後から整える**

です。
