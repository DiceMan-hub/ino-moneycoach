# リサーチ自動化と「反応の追跡」「関連参照」の設計

毎日のリサーチ業務を自動化しつつ、(1) **自分がどんなトピックに反応しているか**を追えるようにする、(2) **他プロジェクトに関連情報があれば自動的に参照候補を出す**、の2つを実現するための設計メモ。

**運用メモ：** Claude Cowork に定期タスクとして依頼済み（反応トピックの追跡・リサーチ提案・関連参照のいずれか／複数）。タスクの詳細や頻度は Cowork 側で確認。

---

## 1. 「自分が反応しているトピック」をどう追うか

### 使えるシグナル（すでに vault にあるもの）

| シグナル | 意味 | 取得方法 |
|:--|:--|:--|
| **LINE に保存したメモ** | 「この内容は後で使いたい」と判断した | `LINE/processed/**/*.md` の `category` + `date`。週ごと・月ごとの category 分布。 |
| **他ドキュメントから LINE へのリンク** | ニュースレター・note・議事録で「この LINE メモを参照した」 | Obsidian のバックリンク、または `grep -r "\[\[LINE/" --include="*.md"`。 |
| **どのフォルダを編集したか** | どのプロジェクトに時間を割いているか | ファイルの `mtime`（最終更新日）。03_NewsLetter / 04_note / 00_Projects ごとの直近 N 日。 |
| **ニュースレターの特集・CTA** | 読者に「これが重要」と伝えたトピック | 段取りやドラフトの「メインテーマ」「今号で参照する LINE メモ」をパース。 |

これらを**集計**すると、「直近で自分が反応しているトピック」がトピック単位（例：マイレージ、クレカ、ANA、JAL、ビジネス、AI）で出せる。

### トピックの出し方（案）

- **粗いが簡単**: LINE の `category`（AI / マイレージ / クレカ / ビジネス）の直近 30 日分の件数 → 多い順が「反応しているトピック」。
- **やや細かく**: LINE の `title` からキーワードを抽出（手動タグ or 単語分割）し、頻出キーワードを「反応トピック」とする。
- **プロジェクトとつなぐ**: 「今週 03_NewsLetter を編集した + 参照した LINE メモの category」→ ニュースレターで反応しているトピック。

---

## 2. 「こういうトピックをリサーチして」へのつなぎ方

### フロー案

1. **週次で「反応トピック」を算出**  
   - 入力: 直近 7〜30 日の LINE 保存（category + title）、他プロジェクト→LINE のリンク、編集したフォルダ。  
   - 出力: 例「今週の反応トピック: マイレージ(5), クレカ(3), ビジネス(2)。キーワード: JAL, AAマイル, 松井証券, 海外送金」。

2. **「リサーチしてほしいトピック」のリストにする**  
   - 上記をそのまま「今週リサーチしてほしいトピック: マイレージ（JAL/AA/松井証券）、クレカ（海外送金）、ビジネス」のように文章化。  
   - 人間が 1 行編集して確定してもよい。

3. **リサーチ実行（段階的に）**  
   - **Level 1（手動）**: 上記リストを「毎日のリサーチ用メモ」や Cursor に貼り、「このトピックで気になるニュース・キャンペーンを検索して要約して」と依頼。  
   - **Level 2（半自動）**: スクリプト or エージェントが「反応トピック」→ キーワードリストを生成 → 検索 API や RSS でニュース取得 → 1 つの Markdown に「今週のリサーチ候補」として保存。人間はそれを流し読みして LINE に送るか要約を追記。  
   - **Level 3（自動）**: 同じくキーワードで取得したニュースを、既存の「ニュース・キャンペーンまとめ」や LINE 形式のメモに自動で追記（要確認・承認ステップを挟む想定）。

まずは **Level 1** で「反応トピック」だけ自動で出し、毎朝そのリストを見て「今日はこのトピックをリサーチする」と決める運用が現実的。

### 実装の置きどころ（案）

- **Obsidian Dataview**: `LINE/processed` の `category` を集計するクエリを 1 ノートに書いておき、「今月保存した LINE メモの内訳」を常に表示する。  
- **小さなスクリプト（Python/Node）**: vault を走査し、直近 N 日の LINE の category/title と、他ファイルの `[[LINE/processed/...]]` を集計 → 「今週の反応トピック」を 1 つの md に書き出す。  
- **Cursor / エージェント**: スキル or プロンプトで「今、vault の LINE とリンク状況を確認して、今週リサーチすべきトピックを 3 つ提案して」と毎日 or 週初に実行。

## 3. 他プロジェクトの関連情報を「自動で参照できる」ようにする

### やりたいこと

- 今編集しているドキュメント（例: ニュースレターの段取り、note の下書き、00_Projects の比較表）に対して、**vault 内の関連する情報**（LINE メモ、他プロジェクトの記事・議事録）を「参照候補」として提示する。

### 関連の決め方（案）

| 方法 | 内容 | 難易度 |
|:--|:--|:--|
| **同じ category** | 編集中ファイルが「マイレージ」特集なら、`LINE/processed/マイレージ/*.md` を一覧。 | 低（フォルダ or frontmatter で category を付与すればよい）。 |
| **キーワード一致** | 編集中の本文・タイトルから語を抽出し、LINE の `title` や 00_Projects / 04_note の見出しと部分一致。 | 中（タイトル・見出しだけでも可）。 |
| **バックリンク** | 「このファイルをリンクしているノート」を表示（Obsidian 標準）。「このファイルがリンクしているノート」の兄弟ノートも候補。 | 低。 |
| **日付の近さ** | 直近 30 日に更新した関連ドキュメントを優先。 | 低（mtime でソート）。 |

### 運用イメージ

- **手動で足す**: 段取りやドラフトのテンプレートに「### 関連参照（候補）」セクションを用意し、**Cursor やエージェントに「このドキュメントに関連する LINE メモと他プロジェクトのノートを 2〜5 本提案して」**と依頼。提案をそのセクションに貼る。  
- **半自動**: 編集中ファイルのパス（例: `03_NewsLetter/_working/...`）とタイトルから category を推測（例: ニュースレター → 今号のテーマが「マイル」なら マイレージ）。その category の LINE と、`00_Projects/Airline Mileage/*.md` などをリストし、1 つの「関連参照候補.md」に書き出す or チャットで返す。  
- **Obsidian プラグイン**: 関連ノートを表示するプラグイン（Local Graph や Various Complements など）を組み合わせ、編集中にサイドバーで「LINE の マイレージ」「00_Projects の 特典航空券」をすぐ開けるようにする。

「完全自動で編集中ファイルにリンクを挿入」より、**「関連参照候補を毎回 1 ブロック提案する」**程度にしておくと、誤挿入が減り、自分で選べる。

### 実装の置きどころ（案）

- **Cursor ルール or スキル**: 「03_NewsLetter / 04_note / 00_Projects 内の md を編集・作成するときは、本文または指定 category に基づき、`LINE/processed` と 00_Projects / 04_note から関連しそうなノートを 2〜5 本挙げ、`## 関連参照候補` として提案する」。  
- **スクリプト**: 引数でファイルパスを渡すと、そのファイルの見出し・frontmatter を読み、LINE の category/title と 00_Projects のファイル名でマッチング → 候補リストを md で出力。  
- **テンプレート**: ニュースレターの段取りに「### 今号で参照する LINE メモ（2〜3本）」「### 関連参照候補（AI提案）」を最初から用意し、Phase 1 で Cursor に「この段取りに合う LINE と他プロジェクトを提案して」と依頼。

## 4. まとめ

| やりたいこと                | 実現のコア                                                      | まず試すこと                                                                         |
| :-------------------- | :--------------------------------------------------------- | :----------------------------------------------------------------------------- |
| **どんなトピックに反応しているか追う** | LINE の category/日付 + 他プロジェクト→LINE のリンクを集計                  | Dataview で「今月の LINE 保存内訳」を 1 ノートに表示。週次で「反応トピック」を目視確認。                          |
| **そのトピックをリサーチしてもらう**  | 反応トピック → キーワードリスト → 「リサーチしてほしいトピック」文章化                     | 毎朝 or 週初に「今週の反応トピック」を見て、Cursor に「このトピックでニュース・キャンペーンを検索して要約して」と依頼（Level 1）。     |
| **他プロジェクトの関連情報を自動参照** | 編集中ドキュメントの category/キーワードと、LINE・00_Projects・04_note を突き合わせ | Cursor ルール or スキルで「このドキュメントに関連する LINE と他プロジェクトを 2〜5 本提案」を毎回実行。段取りの「関連参照候補」に貼る。 |

段階的には、(1) **反応トピックの可視化**（Dataview or 小スクリプト）、(2) **「今週リサーチすべきトピック」の文章化と手動リサーチ**、(3) **編集中ドキュメント向けの関連参照提案**（Cursor で提案だけ）、の順で足していくのが扱いやすい。

## 付録：Dataview 例（今月の LINE 保存内訳）

Obsidian で [Dataview](https://blacksmithgu.github.io/obsidian-dataview/) を使っている場合、以下のクエリを任意のノートに貼ると「今月保存した LINE メモの category 内訳」が表で出る。反応トピックの可視化の第一歩になる。

**今月の LINE メモを category 別に件数表示（反応トピックの可視化）：**

````markdown
```dataview
TABLE length(rows) as "件数"
FROM "LINE/processed"
WHERE date(date) >= date(this month)
GROUP BY category
SORT length(rows) DESC
```
````

※ `date` は LINE の frontmatter の `date` フィールド。日付は ISO 形式（`2026-02-02T10:10:25.384Z`）のままでよい。

**「今月の LINE メモ一覧（日付順）」も欲しい場合：**

````markdown
```dataview
LIST title
FROM "LINE/processed"
WHERE date(date) >= date(this month)
SORT date DESC
```
````
