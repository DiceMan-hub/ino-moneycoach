# 法人決算自動化ツール調査レポート

- 調査日: 2026-03-01
- 目的: kazukinagata/shinkoku（個人確定申告）のような法人決算向けフレームワークの存在調査
- 結論: **法人税申告書（別表）を自動生成するOSSは現時点で存在しない**

---

## 調査の背景

個人確定申告には [kazukinagata/shinkoku](https://github.com/kazukinagata/shinkoku)（MIT, Python, 9,300行）というClaude Code Plugin/Agent Skills対応のOSSがある。これと同等の法人決算向けフレームワークがあるかを調査した。

### shinkokuの概要（比較用）

| 項目 | 内容 |
|------|------|
| 対象 | 個人事業主・副業者の確定申告 |
| 技術 | Python 3.11+ / Pydantic v2 / SQLite / PyYAML |
| 機能 | 帳簿管理（仕訳CRUD・PL/BS）→ 所得税・消費税計算 → e-Tax自動入力 |
| 規模 | スキル20個、CLIサブコマンド94個 |
| 法人対応 | `/incorporation`（法人成り相談）のみ。法人決算は明示的に対象外 |

## 1. AIエージェント/Claude Code向けプラグイン

### kazukinagata/shinkoku（個人のみ）
- URL: https://github.com/kazukinagata/shinkoku
- Stars: 220 / License: MIT
- 法人税対応: なし（ロードマップにも計画なし）
- 帳簿管理部分（仕訳・PL/BS）は法人版のベースとして転用可能

### freee MCP Server（公式）
- URL: https://github.com/freee/freee-mcp
- Stars: 177 / License: Apache-2.0 / 言語: TypeScript
- 対応API: 会計・人事労務・請求書・工数管理・販売
- 法人決算での活用: freee会計APIで仕訳・試算表データを取得可能。**決算書・別表の自動生成機能はなし**
- 認証: OAuth 2.0 + PKCE
- 評価: freee会計で帳簿管理している法人なら「データ取得層」として使える

### 実用レベル

| ツール | 価格 | 対応範囲 | 形式 | 備考 |

| 法人税申告お助けくん（ニコラソフト） | 8,500円/2年 | 別表6系、地方法人税・市民税 | デスクトップ | 会計データ入力→申告書一式を自動生成 |

### VBA法人税確定申告書の詳細（無料で最も実用的）
- URL: http://www.soft-j.com/vbasoft/hojin.html
- 最新版: 令和07年版 VER 5.11
- 構成:
  - `hojin0704.xlsb`: 法人税申告書・別表1〜16・適用額明細書・OCR用申告書
  - `hojin_hyo0704.xlsb`: 法人税別表6〜6(27)の表示
  - `hojin_tih0704.xlsb`: 事業税・県民税・市民税の申告書
- 制限: 資本金1億円超非対応、電子申告義務化非対応、外形標準課税非対応
- AIエージェント連携: VBAフォーム入力のため自動化は困難

## 4. e-Tax法人版 / eLTAX 関連

### e-Tax API（国税庁）
- URL: https://www.e-tax.nta.go.jp/shiyo/api.htm
- HTTPベースAPI。申告参考情報の取得が可能
- APIキーの発行申請が必要（メールで申請書提出）
- **別表CSV標準フォーム**: 別表の明細部分をCSVで提出可能
  - URL: https://www.e-tax.nta.go.jp/hojin/gimuka/csv_jyoho2_beppyo_04.htm
  - Pythonで生成→e-Tax取込は技術的に可能

### eLTAX API（地方税）
- 公開仕様書に基づく送受信モジュール＋電子署名モジュール
- OSSツールは皆無。電子署名のハードルが高い

## 6. OSSが存在しない理由

1. **構造的複雑さ**: 別表が20種以上あり相互参照が多い
2. **地方税の多様性**: 事業税・住民税が必須で自治体ごとに差異がある
3. **税制改正の追従コスト**: 毎年の改正に対応し続ける必要がある
4. **市場構造**: 商用ソフト（freee申告・達人シリーズ・JDL等）の独壇場

---

## 7. 現実的な選択肢

### A. 最小コスト路線
- 帳簿管理: freee会計 + freee MCP Server（Claude Codeから操作）
- 申告書: 全力法人税（初年度無料）or VBA法人税（無料）
- メリット: 低コスト、すぐ使える
- デメリット: 一気通貫の自動化は不可

### B. DIY路線（shinkokuアーキテクチャ転用）
- 帳簿管理: shinkokuの仕訳エンジン（Pydantic + SQLite）をフォーク
- 決算書: PL/BS/株主資本等変動計算書をPython（openpyxl）で生成
- 税額計算: 法人税計算ロジックを自作
- 申告書: e-Tax CSV標準フォームを出力ターゲットに
- メリット: 完全自動化が可能
- デメリット: 工数が数ヶ月級、税務知識が必須

### C. 既存SaaS活用
- freee会計 + freee申告（一気通貫）
- メリット: 帳簿→決算→申告がシームレス
- デメリット: 月額コスト、カスタマイズ性は低い

## 8. 既存個人確定申告システム（shinkoku_complete）との関係

自分の個人確定申告システム（`~/Dropbox/確定申告/shinkoku_complete/`）は投資家向け（株式・配当・FX）に特化。法人決算とは対象が異なるが、以下のアーキテクチャパターンは転用可能：

- Pydantic v2によるデータモデル定義・バリデーション
- YAML設定ファイルによる年度データ管理
- openpyxlによるExcel出力（集計表・決算書）
- SQLiteによるデータ永続化
- 計算層（pure functions）と出力層の分離

- 税理士いらずの公式サイト（z-irazu.jp）はSSL証明書切れ
- shinkokuの法人対応についてIssueでの議論は確認できなかった（Issue 0件）
- e-Tax APIの法人向け機能の詳細仕様はAPIキー取得後でないと確認不可
